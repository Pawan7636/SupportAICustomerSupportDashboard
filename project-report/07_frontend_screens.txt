================================================================
  APPLICATION SHELL
================================================================

The entire frontend is a single React component tree in src/App.tsx.
There is no React Router — navigation is controlled by a single
state variable:

  type Screen = "dashboard" | "assistant" | "human" |
                "faqs"      | "history"   | "escalations"

The App root renders:
  - <Login />           when loggedIn === false
  - <Shell /> + active screen  when loggedIn === true

================================================================
  SCREEN: LOGIN
================================================================

Component: Login({ onLogin })
Route equivalent: /login (shown when not authenticated)

What it does:
  - Email + password form
  - "Remember me" checkbox
  - "Forgot password" button (UI only)
  - "Create an account" link (UI only)
  - On submit: sets loggedIn = true (demo mode — not wired to API)

Note: The login screen is currently a demo UI. The backend
      has a full /api/auth/login endpoint ready to wire up.

================================================================
  SCREEN: AI ASSISTANT
================================================================

Component: Assistant({ onToast })
Nav item: Sparkles icon, "AI Assistant"

This is the core live feature — fully connected to the backend.

LEFT CARD — Composer:
  - Textarea for customer query (max 2000 chars, with counter)
  - Category selector: Orders / Payments / Refunds / Account / General
  - Tone selector: Friendly & professional / Concise / Empathetic
  - Gemini AI + RAG note (branding)
  - "Generate response" button (disabled while loading)

RIGHT CARD — Response:
  - Shows streaming text as it arrives (typing cursor during stream)
  - "Streaming…" badge while generating, "Ready" badge when done
  - RAG source citations panel (blue chips with article title + score%)
    shown below the response when ragEnabled = true
  - Footer: Copy response button, Regenerate button,
    "RAG · Gemini AI" or "Gemini AI" attribution
  - Error state with "Try again" button on failure

API calls:
  POST /api/chat/stream   (SSE streaming, relative URL)

SSE handling:
  - First event parsed for { sources, ragEnabled }
  - Subsequent events accumulate text chunks into full response
  - { done: true } ends the stream

State:
  query, category, tone, response, generated, loading, error,
  sources, ragEnabled, abortController

================================================================
  SCREEN: FAQ MANAGEMENT (KNOWLEDGE BASE)
================================================================

Component: FaqManagement({ onToast })
Nav item: FileQuestion icon, "FAQ Management"

Fully connected to the backend /api/kb endpoints.

Toolbar:
  - Search input (filters by title and content client-side)
  - Category filter tabs: All / Orders / Payments / Refunds /
    Account / Technical / General

Article list:
  - Category icon, title, category badge, content preview (160 chars)
  - Tags row (comma-separated chips)
  - "Updated <date>" from updated_at
  - Edit button → opens modal
  - Delete button → DELETE /api/kb/:id with spinner

Loading state: spinner while fetching
Error state: retry button if fetch fails
Empty state: "No articles found" with search icon

Add/Edit modal:
  - Category selector
  - Title input
  - Content textarea (6 rows)
  - Tags input (comma-separated, displays as chips preview)
  - Save / Cancel buttons with loading spinner

API calls:
  GET    /api/kb?category=...    (on mount and category change)
  POST   /api/kb                 (create)
  PATCH  /api/kb/:id             (edit)
  DELETE /api/kb/:id             (delete)

Footer: article count, "Knowledge base synced with Gemini RAG"

================================================================
  PRIMITIVE COMPONENTS
================================================================

All built from scratch — no external component library.

Button({ children, variant, icon, onClick, type, disabled, className })
  Variants: primary | secondary | ghost | danger
  Rendered as <button> with .btn .btn-{variant} classes

Badge({ children, tone })
  Tones: green | amber | red | blue | purple | gray
  Rendered as <span> with colored dot + text

Input({ label, icon, type, placeholder, value, onChange, required })
  Wraps <input> with optional label and icon prefix

SelectField({ label, value, onChange, children })
  Wraps <select> with label and chevron icon

Card({ children, className })
  <div class="card"> — white surface with shadow and border

PageHeader({ title, description, action })
  Page title + description + optional action button on the right

Avatar({ name, color })
  Initials-based avatar circle in purple/blue/green/etc.

Modal({ title, description, onClose, children })
  Backdrop + centered dialog with close button
  Clicking backdrop also closes

================================================================
  GLOBAL STATE
================================================================

App root state:
  loggedIn      boolean         — drives Login vs Shell render
  screen        Screen          — currently active screen
  sidebarOpen   boolean         — mobile sidebar state
  toast         string          — ephemeral notification text

Toast system:
  showToast(message) sets toast text, auto-clears after 2800ms
  Rendered as a fixed-position bottom bar with CheckCircle2 icon
